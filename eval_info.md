# Benchmarking the Quality of Intermediate Decisions in Win/Loss Card Games

## TL;DR
- **Build a learned win-probability (value) model and score every move by how much it changes win probability (a "win-probability-added" metric); this is the single most practical, directly-transferable tool for ranking your models' intermediate decisions when only win/loss is known.** Pair it with curated puzzle/scenario suites (where you DO know the right answer) and head-to-head Elo from self-play.
- Yes, conditional/puzzle-style task suites are a good idea — they are exactly how chess (Strategic Test Suite), Pokémon (PokéChamp's 1,000 curated 1v1 scenarios), and Hearthstone ("find lethal" puzzles) sidestep the missing-ground-truth problem. Use them as a complement, not a replacement, for value-based and play-based metrics.
- No single metric is trustworthy alone. Combine three layers: (1) process metrics vs. a strong reference (agreement rate, value/centipawn-style loss, regret); (2) a learned value model for win-probability-added and counterfactual scoring; (3) outcome metrics (Elo, win rate) over large samples to average out luck. Always report calibration and sample size.

## Key Findings
- The core obstacle is the **credit assignment problem**: with sparse, delayed, binary rewards, you cannot directly tell which of the many intermediate moves caused the win. RL's standard answer is to learn a **value function** that predicts expected outcome from a state, then judge each action by how it moves that value.
- The most transferable evaluation idea across chess, poker, and sports is the same: **use a value/win-probability model as a proxy for ground truth.** Chess uses engine "centipawn loss," sports use "Win Probability Added (WPA)," and AlphaZero-style agents use a learned value head. All measure "how much did this action change my expected result?"
- **Process beats results on small samples.** Poker's "resulting" fallacy (Annie Duke) and sports' "decisions vs. outcomes" framing both warn that a good move can lose and a bad move can win. To benchmark decision quality you must measure the *process* (move quality vs. a reference) separately from the noisy *outcome*.
- **Puzzle/conditional suites work and are already used in card games.** PokéChamp built a benchmark of 1,000 curated 1v1 Pokémon scenarios each with a guaranteed feasible win; Hearthstone's "find lethal" puzzles are formally studied. These give you known-answer test positions — exactly the "set of conditional tasks" the user asked about.
- **Card-game-specific precedent exists.** The 2026 MTG-Causal-RL benchmark explicitly argues scalar win rate is insufficient and makes per-factor credit, calibration, and cross-archetype transfer first-class metrics — a directly relevant template for MTG/Hearthstone/TCG evaluation.

## Details

### 1. The credit assignment problem (the root issue), explained simply
In your setting the agent makes many moves and only gets one bit of feedback at the end (win or loss). The **credit assignment problem** is: which moves deserve credit/blame? This is described as "one of the biggest challenges in RL," and it is "aggravated under sparse binary rewards, especially when rewards are given only after successful completion of the task."

RL's main tools, in plain terms:
- **Value function V(s):** a learned estimate of "expected final outcome (e.g., win probability) from this state." It is the workhorse. Once you have it, you can score actions.
- **Temporal-difference (TD) learning:** instead of waiting for the end of the game, you update a state's value toward the value of the *next* state plus any immediate reward: `V(s) ← V(s) + α[r + γV(s') − V(s)]`. The bracket is the "TD error." Intuition: you "update the value of a state based on the estimated value of the next state" — learning bit by bit rather than all at once. This is how outcome signal propagates backward to earlier moves.
- **Monte Carlo returns:** the simpler alternative — wait until the game ends, then assign the final result to every state visited. Unbiased but high variance (a single lucky win credits every move, good or bad).
- **Advantage estimation:** A(s,a) = Q(s,a) − V(s) = "how much better than average is this action in this state?" This is essentially the per-move quality score you want.
- **Reward shaping / potential-based reward shaping (PBRS):** add a helper reward based on a "potential" Φ(s) that estimates how good a state is, shaped as `F(s,s') = γΦ(s') − Φ(s)`. Ng, Harada & Russell (1999) proved that this exact form is **policy-invariant** — it does not change the set of optimal policies, only speeds learning. The key insight for evaluation: *the change in a good potential function is itself a per-move quality signal.*

The deep point (from the credit-assignment literature): simply making rewards non-sparse does NOT solve credit assignment — adding a constant to every reward removes sparsity but changes nothing. The real solution is a good value/potential estimate.

### 2. Evaluation methodology: measuring move quality when only outcomes are known
This is the heart of the user's question. Four families of methods, all transferable.

**(A) Win probability / value model as a proxy for ground truth.** Train a model that maps a game state to estimated win probability, then score each move by the change in win probability it produced. This is exactly:
- **Chess "centipawn loss" (ACPL):** for each move, compare the engine's evaluation of the best move to the move actually played; the gap (in centipawns, 1/100 of a pawn) is the loss. "The fewer centipawns one loses per move, the stronger the play." Average centipawn loss (ACPL) over a game/many games is a standard quality metric, computed against Stockfish.
- **Sports "Win Probability Added (WPA)":** "the change in win probability between two consecutive game states," used to "evaluate in-game decision making." In football the analog is "Expected Points Added (EPA)." McFarlane's "Expected Threat-type Metric" (ETM) is literally "the difference between the win probability of the actual decision and that of the theoretically optimal decision."
- **AlphaZero-style value head:** a neural net that, "given a board position... estimates the probability for each player to ultimately win the game." This learned value is trained purely from self-play win/loss outcomes — exactly your data situation.
- **What it requires:** a value model (logistic regression on hand-built features is enough to start; a neural net if you have data). **Strength:** gives a continuous per-move score with no human labels. **Pitfall:** the metric is only as good as the model's calibration — "calibration, not just accuracy, is the primary quality criterion." A miscalibrated value model produces misleading move scores. Also, losing X centipawns in a won position ≠ losing X in a tied position; raw value-deltas need normalizing (this is why win-probability units are often better than raw eval units).

**(B) Regret vs. a strong reference policy or solver.** If you have a near-optimal reference, score each move by how much expected value it gave up versus the reference's best move ("regret" or "blunder rate").
- **Poker:** measure **exploitability** (a.k.a. Nash distance) — "how much a perfect counter-strategy could win against your current policy" — typically in **milli-big-blinds per game (mbb/g)**: "how many thousandths of a big blind one player wins on average per hand." Nash equilibrium has zero exploitability; the Cepheus agent reached an exploitability of **0.986 mbb/g** in heads-up limit Hold'em — per Bowling, Burch, Johanson & Tammelin, "Heads-up Limit Hold'em Poker Is Solved," *Science* 347(6218), 2015, whose strategy "reaches an exploitability of 0.986 mbb/g, making HULHE essentially weakly solved." You can also report a **blunder rate** = fraction of moves losing more than a threshold of EV vs. the solver.
- **What it requires:** a solver or a much stronger reference agent. **Strength:** principled, interpretable. **Pitfall:** real card games (MTG, Hearthstone) are far too large to solve exactly to a Nash equilibrium, so a true solver usually does not exist — you fall back to "strongest available agent" as an imperfect reference.

**(C) Best-move agreement / accuracy vs. a strong reference engine.** Simpler than regret: just measure the fraction of moves where your model picks the same move as the strong reference (or one of its top-k). Chess "Let's Check" reports a "miss" when a move "does not match an engine's top choice." Easy to compute and explain. **Pitfall:** punishes reasonable moves that merely differ from the reference, and treats a tiny error the same as a catastrophic one — agreement rate should be paired with a magnitude metric (value loss).

**(D) Puzzle suites / curated conditional test positions (directly answers the user's "conditional tasks" idea).** Construct or collect positions where the correct answer is known or strongly agreed, then score models by how often they get them right.
- **Chess Strategic Test Suite (STS):** 1,500 positions in 15 strategic themes of 100 each (Dann Corbit & Swaminathan Natarajan, 2009–2010), each with solution moves scored 1–10 by strong engines; an engine's total score (out of 15000) measures positional understanding. The revised STS-Rating v6 by Ferdinand Mosca retains 1,188 positions, and DeepMind's "Diversifying AI: Towards Creative Chess with AlphaZero" (arXiv:2308.09175) used STS as "a data set of 1088 single-step, multi-choice chess puzzles." The scoring methodology is concretely validated by Lai's "Giraffe: Using Deep Reinforcement Learning to Play Chess" (arXiv:1509.01549), where scores are "added up to a score out of 15000," improving "from approximately 6000/15000... to approximately 9500/15000, with peaks above 9700/15000" as training progressed. Crucially, "positions from the test suite have never been used in any stage of training" — a clean held-out test set.
- **Card-game precedent already exists:** PokéChamp (Karten, Nguyen & Jin, "PokéChamp: an Expert-level Minimax Language Agent," ICML 2025, arXiv:2503.04094) "created a benchmark of 1,000 1v1 battle scenarios... each scenario... is carefully selected to ensure a feasible win condition... we rejected samples that could not be won by the Abyssal bot" — a direct card-game analog to a tactics suite. Hearthstone's "find lethal" (mate-in-1) puzzles are formally studied: Hoffmann, Lynch & Winslow, "Mad Science is Provably Hard: Puzzles in Hearthstone's Boomsday Lab are NP-hard," *Journal of Information Processing* 28:919–928 (2020), "consider the computational complexity of winning this turn (mate-in-1 or 'finding lethal')... and prove the various puzzle types in each generalization NP-hard" (via reductions from 2-partition and 3-partition). This confirms that constructed win-this-turn scenarios are a meaningful, well-defined task class.
- **What it requires:** effort to build/curate scenarios and to establish "correct" answers (via a strong solver/agent or expert consensus). **Strength:** gives true ground truth on a controlled slice; isolates specific skills (lethal, removal timing, sequencing, mulligan); reproducible and cheap to re-run; immune to outcome luck. **Pitfall:** coverage — puzzles test the situations you thought to include, not the full distribution of real play; models can overfit to the suite; building them is labor-intensive.

### 3. Process-level vs. outcome-level metrics
Card games, like poker, have high variance: a great line can lose to a topdeck. Poker calls the error of judging a decision by its result **"resulting"** — Annie Duke (*Thinking in Bets*, 2018) defines it as "our tendency to equate the quality of a decision with the quality of its outcome." Her central framing: "Thinking in bets starts with recognizing that there are exactly two things that determine how our lives turn out: the quality of our decisions and luck."

Implication for benchmarking:
- **Process metrics** (move-quality vs. a reference value model, agreement rate, regret) measure decision quality directly and need far fewer games to be statistically meaningful.
- **Outcome metrics** (win rate, Elo) are the ultimate truth but are noisy; you need large samples to average out luck.
- Best practice: report both, and treat divergence as informative (a model with good process metrics but mediocre win rate may just be unlucky or facing variance; a model winning with poor process metrics may be exploiting weak opponents).

### 4. Counterfactual / value-based and off-policy evaluation
- **Counterfactual win-probability-added:** using your learned value model (or a simulator), estimate for each action "how much did this change expected win probability vs. the alternative(s)?" This is the WPA idea applied move-by-move. With a simulator you can roll out alternatives; with just a value model you compare V(s_after_chosen) to V(s_after_alternatives).
- **Off-policy evaluation (OPE):** a family of RL methods to "estimate the expected cumulative reward of a target policy using logged trajectory data generated from a different behavior policy, without executing it." Useful if you want to estimate how good a model would be from existing game logs without playing fresh games. Key high-level point: "OPE is a strictly easier task than policy optimization" — evaluating a fixed policy needs coverage only along that policy's trajectories. Main estimator families: importance sampling (unbiased, high variance), direct/model-based (lower variance, possibly biased), and doubly-robust hybrids. **Pitfall:** importance-sampling variance explodes over long horizons (card games are long), so naive OPE is hard here; model-based/value-based direct estimates are often more practical.

### 5. Reference-policy comparison and self-play benchmarking
- **Elo / TrueSkill from head-to-head play:** rate models by win/loss against each other. Elo uses a logistic model: P(i beats j) = 1/(1+10^((r_j−r_i)/400)). AlphaZero used Elo to track training. **TrueSkill** extends Elo to multiplayer and adds an uncertainty estimate, so "performance estimates more quickly adjust for new algorithms." **Pitfall:** Elo can be distorted by non-transitive matchups ("rock-paper-scissors" archetypes, very common in card games) and by "clones" of similar agents; report the pool composition.
- **Agreement with expert/human play & behavioral cloning baselines:** train a behavioral-cloning model on strong human games and measure how closely a model matches expert moves, or use BC as a baseline opponent. BC is "the simplest entry point to imitation learning" but "suffers from covariate shift / compounding error" — once the agent deviates it sees states never in the expert data. So BC agreement is a fine reference signal but a weak standalone opponent.

### 6. Card-game-specific and directly-transferable precedents
- **MTG-Causal-RL (2026):** a Gymnasium benchmark on Magic: The Gathering with a 3,077-dim observation and 478-action masked space. Its central claim matches the user's intuition exactly: scalar win rate is not enough, so it makes "causal credit assignment, leave-one-out cross-archetype transfer, and policy auditability first-class benchmark metrics." Concretely it:
  - Learns a **WinProb model** as a logistic regression over six hand-designed strategic factors — **card advantage, board pressure, tempo, life buffer, threat density, removal availability** — refit online from terminal game outcomes (a 2,000-game outcome buffer, refit every 200 games). This is a card-game value model you can copy.
  - Computes **per-factor credit traces**: for each factor k, a per-step reward = change in that factor, a per-factor advantage from a per-factor critic, and an SCM-predicted intervention effect; then measures **calibration** as the Pearson correlation between the agent's learned factor-advantage and the predicted effect, plus a sign-agreement rate and per-factor "credit share." This is a concrete recipe for attributing the outcome to interpretable intermediate factors.
  - Uses **potential-based reward shaping** with those same factors as the potential Φ (following Ng et al. 1999), computed only from agent-observable quantities to preserve policy-invariance under partial observability.
  - Reports a **leave-one-out cross-archetype transfer gap** = (in-distribution win rate − held-out-archetype win rate), to test generalization beyond the training opponent pool. (Caveat: the paper's headline win-rate and transfer numbers use only 2 paired seeds and are explicitly labeled exploratory; the *metric definitions* are the transferable contribution, not the specific numbers.)
- **Hearthstone:** the AAIA'17 "Helping AI to Play Hearthstone" challenge framed evaluation as predicting **win probability from a mid-game state**, scored by **AUC** — i.e., it benchmarked the value model itself. Researchers note that historically "there has not been yet proposed any universal benchmarking method" for Hearthstone beyond human observation and self-play, underscoring why a value-model + puzzle-suite approach is valuable.
- **Pokémon:** PokéChamp's curated 1,000-scenario puzzle benchmark (feasible-win positions) and the large-scale PokéAgent Challenge show the field moving toward curated scenarios plus head-to-head ladder play.
- **Board game engines (chess/Go) and poker solvers** supply the mature, battle-tested templates (centipawn loss, STS, value heads, exploitability/mbb/g, Elo) that the card-game work is now adapting.

## Recommendations
A simple, prioritized plan you can actually implement. Stage them; later stages are worth it only if earlier ones leave questions.

**Stage 1 — Cheap, do first (days):**
1. **Self-play Elo / round-robin win rate.** Have all your models/approaches play many games against each other and against fixed baselines (random, a greedy/heuristic bot, a behavioral-cloning bot trained on strong logs). Report Elo (or TrueSkill for >2 players) with confidence intervals and enough games to shrink luck. This is your outcome-level ground truth. Threshold to act: if Elo differences are within confidence intervals, you need more games or better process metrics before concluding anything.
2. **Best-move agreement vs. your strongest available agent.** Measure how often each model matches the top move (and top-3) of your best reference. Quick, interpretable first cut.

**Stage 2 — The core of your benchmark (1–3 weeks):**
3. **Build a win-probability value model.** Start with logistic regression over a handful of hand-built features (card advantage, board presence/tempo, life totals, cards in hand, removal available — directly borrow MTG-Causal-RL's six factors). Train it on the win/loss outcomes you already have. Check **calibration** (do predicted 70% spots win ~70% of the time?) before trusting it — calibration is the primary quality criterion.
4. **Score every move by Win-Probability-Added.** For each move, compute the change in your value model's win probability (and, where you can simulate alternatives, the gap to the best alternative = a regret/"centipawn-loss" analog). Aggregate per model as average WPA loss and a **blunder rate** (fraction of moves losing more than a set win-prob threshold). This is your primary process-level decision-quality metric, and it needs no ground-truth labels.

**Stage 3 — Conditional/puzzle suites (yes, build them) (2–4 weeks):**
5. **Construct a puzzle suite of conditional tasks** — this directly implements your idea and is strongly endorsed by precedent (chess STS, PokéChamp, Hearthstone lethal puzzles). Curate scenarios where the answer is known or strongly agreed: "find lethal this turn," "correct removal target," "correct sequencing/mana use," "keep or mulligan." Get "correct" answers from your strongest agent's deep search and/or expert consensus, and **hold these positions out of all training.** Score models by points (allow partial credit for near-best moves, as STS does). Organize by theme so you get a skill-by-skill profile, not just one number.

**Stage 4 — Optional depth:**
6. **Per-factor credit/calibration** (MTG-Causal-RL style) if you want interpretable attribution of outcomes to strategic factors.
7. **Off-policy evaluation** only if you must rank policies from logs without fresh play; prefer model/value-based estimators over importance sampling given long card-game horizons.

**How to combine the metrics:** treat them as a dashboard, not a single score. Use Elo/win rate as the outcome anchor; use WPA-loss/blunder-rate and puzzle scores as the decision-quality core (these discriminate models on far fewer games and isolate skill from luck); use agreement rate and per-factor calibration as diagnostics that explain *why* a model is better or worse. When metrics disagree, that is signal: strong process metrics + weak win rate usually means variance or a tough opponent pool; strong win rate + weak process metrics usually means opponent-exploitation that may not generalize. Always report calibration of the value model and the sample size / confidence intervals.

## Caveats
- **Every value-model metric inherits the value model's blind spots.** If your win-probability model is wrong or miscalibrated, WPA, regret, and counterfactual scores are all wrong in the same direction. Validate calibration first, and prefer win-probability units over raw eval units (a 100-point swing means different things in a tied vs. decided game).
- **No true solver exists for full MTG/Hearthstone/Pokémon TCG.** Unlike poker's solvable subgames (heads-up limit Hold'em was weakly solved to 0.986 mbb/g), these games are too large; your "reference" is only your strongest agent, so regret/agreement metrics are relative, not absolute.
- **Outcome variance is large.** Binary win/loss with heavy luck (draws, hidden info) means win-rate/Elo need big samples; this is precisely why process and puzzle metrics are valuable.
- **Non-transitivity breaks single rankings.** Card-game archetypes are often rock-paper-scissors; Elo can mislead. Report the opponent pool and consider archetype-by-archetype results plus cross-archetype transfer gaps.
- **Puzzle suites have coverage and overfitting risk.** They test only the situations you included and can be gamed; keep them held-out, refresh them, and never use them as the sole metric.
- **The MTG-Causal-RL empirical numbers are preliminary** (a 2026 v1 preprint with only 2 seeds on headline results, self-admittedly exploratory); adopt its *metric definitions and structure*, not its specific win-rate figures.
- **Behavioral cloning baselines drift** (covariate shift), so agreement-with-BC is a useful signal but BC is a weak standalone opponent or reference at states off the expert distribution.
